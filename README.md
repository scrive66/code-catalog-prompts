# コードカタログ・プロンプト集

既存コードから「多数派の作法」を掘り出してカタログ化し、(1) instructions の材料にし、
(2) 多数派から外れたバグ候補の監査に使うための、VS Code Copilot Chat 向けプロンプト4点セット。
白紙からルールを書かず、「掘る → 選ぶ → 指示化する」ための道具。

## ファイル構成

| ファイル | 役割 | モード |
|---|---|---|
| `01-catalog-generate.prompt.md` | 既存コードを調査し、証拠（実施率・path:line）付きの多数派カタログ `docs/code-catalog.md` を生成 | Agent |
| `02-deviation-audit.prompt.md` | カタログの「確立した作法」と実コードを突き合わせ、不在のバグ候補を監査 → `docs/deviation-audit.md` | Agent |
| `03-to-instructions.prompt.md` | カタログで `[採用]` 印を付けた項目だけを instructions 下書きに変換 → `docs/instructions-draft/` | Agent |
| `04-tacit-interview.prompt.md` | コードから読めない暗黙知だけを最大7問で聞き取り、ルール案と例外リストに整形 | Ask |

## 使い方（VS Code + GitHub Copilot）

### 方法A: プロンプトファイルとして使う（推奨）
対象プロジェクトの `.github/prompts/` に4ファイルをコピーし、Copilot Chat で
`/01-catalog-generate` のようにスラッシュコマンドで呼び出す。
frontmatter 付きなので、そのままプロンプトファイルとして認識される。

### 方法B: 貼って使う
各ファイルの frontmatter（`---` で囲まれた部分）を取り除き、本文をそのまま
Copilot Chat（Agent モード）に貼る。対象範囲や出力先を変えたい場合は、
本文の「入力」欄を書き換えてから貼る。

## 回し方（推奨フロー）

1. **01を実行** → `docs/code-catalog.md` ができる
2. **カタログを人間が検分**する。採用したい作法に `[採用]` と印を付ける。
   「分裂項目」は無理に統一せず、そのままにしておくのが正解
3. 必要に応じて **04を実行**し、コードから読めない例外・禁止事項を補う
   （出力される「登録済み例外」をカタログに追記しておくと、02の誤検出が減る）
4. **03を実行** → instructions の下書きができる。検分して `.github/` へ配置する
5. **02を実行** → 逸脱監査レポートができる。優先度「高」から目視確認する。
   確認結果は次のどちらかに還流させる:
   - 本物のバグだった → 修正し、カタログの作法として確定
   - 意図的だった → 理由をカタログの「登録済み例外」に追記（次回監査で除外される）
6. コードベースが育ったら 01 を再実行してカタログを更新する（差分確認を推奨）

## 設計上の約束（全プロンプト共通）

- **読み取り専用**。01・02 は調査対象コードを変更しない。03 も下書きフォルダにしか書かない
- **証拠なしのルールを作らない**。全項目に実施率と代表例（path:line）を必須化し、
  採用率60%未満はルール化せず「分裂項目」に回す
- **意図的例外を守る**。逸脱はまず「説明可能か」を反証チェックしてから候補に残す
- **自動修正しない**。発見と報告までが仕事。直すかどうかは人間が決める

## 注意

- 母数が小さいプロジェクトでは実施率が暴れる。サンプル不足の項目は鵜呑みにしない
- 生成されたカタログは「今のコードの姿」の記録であり、正しさの証明ではない。
  多数派が間違っているプロジェクトでは、間違いもカタログ化される（だから検分工程がある）
- 大規模リポジトリでは 01 の「深さ」を絞るか、ファミリー単位で分割実行すること
