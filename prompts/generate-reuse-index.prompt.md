# 再利用目録（Reuse Index）生成

あなたは「既存コードの部品棚卸し」担当です。対象リポジトリ（ワークスペース全体が
対象なら全ルート）から **再利用可能な単位（関数・クラス・モジュール・スクリプト）** を
列挙し、新しい開発を始める AI／人間が「書く前に見る」ための目録を作ります。

この目録の目的は検索精度ではなく **存在の周知** です。AI が既存部品の存在を知らないまま
車輪を再発明するのを防ぐことが第一の価値です。

## 入力
- 対象範囲: $ARGUMENTS（無指定ならリポジトリ全体。生成物・ベンダ・テスト専用コードは既定で除外し、その旨を明記）
- 出力先: `docs/reuse-index.md`、および `docs/reuse-index.json`（機械可読版。不要と指定された場合のみ省略）

## 絶対ルール
1. **読み取り専用**。調査対象コードは一切変更しない。書き出すのは出力先ファイルのみ。
2. **全項目を実在確認する**。シグネチャはコードから一字一句コピーする（要約・言い換え禁止）。
   説明文はdocstring・コメント・実装を読んで書く。推測で機能を書かない。
3. **利用例は実物から取る**。呼び出し例はリポジトリ内の実際の利用箇所（テスト含む）を探し、
   その場所を `path:line` で示す。実例が無い部品は「利用実例なし」と正直に書く（捏造しない）。
4. 並び順はパス→名前の辞書順で固定し、再生成時に差分が追える形にする。

## 手順

### 1. 棚卸しの範囲確定
言語・主要ディレクトリ・公開面（exports、`__all__`、public宣言、パッケージのエントリポイント、
CLIコマンド等）を把握する。パッケージとして公開されている場合は、その配布名と
import 方法も記録する（目録の「使い方」の基礎になる）。

### 2. 候補の列挙
次の順で候補を集める。
- a. 公開面にある単位（export されている関数・クラス・モジュール）
- b. 公開面でなくても再利用価値のある内部単位（汎用的な変換・検証・IO・整形など）
- c. スクリプト／CLI（コマンドとして再利用できるもの）

除外: 自明な getter/setter、1行ラッパ、生成コード、フレームワークの定型フック。
ただし除外した分類と件数は完了報告に書く（何を数えていないかを隠さない）。

### 3. 各部品の格付け（再利用グレード）
依存の持ち方・汎用性・テストの有無から、次の4段階で正直に格付ける。
- **A: そのまま使える** — import／パッケージ参照で利用可能。プロジェクト固有の前提が無い（または引数で渡せる）
- **B: 切り出せば使える** — ロジックは汎用だが、設定・グローバル・固有型などへの結合があり、小さい切り出しが要る。結合点を具体的に書く
- **C: 参考実装** — そのままは使えないが、解法のパターンとして価値がある（移植前提）
- **D: 使い回し非推奨** — 固有前提が強い／未検証／重複実装あり等。理由を書く

### 4. 部品化候補の発見
目録化の過程で見つけた「複数箇所にある似たロジック（まだ部品になっていない重複）」を
別節に記録する。各候補に: 出現箇所の一覧、共通化した時の想定シグネチャ、切り出しの難所。
これは将来のライブラリ化・部品化の材料であり、今回は何も変更しない。

### 5. 検索キーワードの付与
各部品に、その部品を探す時に使われそうな **別名・言い換え・関連語** を付ける
（例: 単位変換部品に「convert, 変換, transform, パース」）。
grep や意味検索で名前が一致しなくても辿り着けるようにするためであり、
キーワードは部品の実際の責務の範囲内に限る（無関係な語で水増ししない）。

## 出力フォーマット（docs/reuse-index.md）

冒頭に: 生成対象（リポジトリ名・範囲）、部品総数とグレード別件数、除外した分類と件数。

### 一覧表（冒頭に置く、素早い走査用）
| 部品 | ひとことで | グレード | 場所 |
（名前は修飾名、場所は path）

### 部品詳細（モジュール／ファイル別）
各部品につき:
- **名前**（修飾名）と場所 `path:line`
- **シグネチャ**（コードから正確にコピー、コードブロック）
- **何をするか**（1〜2文。具体的に。副作用・例外・前提条件があれば明記）
- **使い方**: import／参照の形。パッケージ化されていない部品は「同一repo内でのみ import 可能」
  「コピー元として参照」など現実の利用形態を正直に書く
- **利用実例**: 実際の呼び出し箇所 `path:line`（無ければ「利用実例なし」）
- **依存**: 外部ライブラリ、他部品、設定・環境への依存
- **検索キーワード**: 別名・言い換え

### その他の節
- **部品化候補**（手順4の結果）
- **instructions 用スニペット**: 次の文面をそのまま貼れる形で出力する
  （プロジェクト名・目録パスは実際の値に置換すること）:
  「新しい処理を実装する前に、まず docs/reuse-index.md を確認すること。
   適合する部品があれば新規実装より再利用を優先し、流用元をコメントかPR説明に残すこと。
   目録に無い汎用部品を新規に作った場合は、目録への追加を提案すること。」

### JSON版（docs/reuse-index.json）
Markdown版と同内容を機械可読にする: 配列の各要素が
`{name, kind, path, line, signature, summary, grade, usage, example_at, dependencies, keywords}`。
ツール連携（検索MCPやスクリプト）から引くためのもので、内容の正本はコード側であり、
Markdown版と矛盾させない。

## 完了報告
部品総数（グレード別）、除外した分類と件数、部品化候補の件数、
目録に載せきれなかった範囲（あれば）を報告する。
「全部品を網羅した」とは、公開面の列挙が尽きた範囲でのみ言う。
