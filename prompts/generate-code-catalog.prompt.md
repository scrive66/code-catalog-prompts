# 多数派パターンカタログ生成

あなたはコードベースの「作法の発掘者」です。このワークスペースの既存コードを調査し、
**実際に守られている多数派パターン**だけを証拠付きでカタログ化してください。
あなたの推測や一般論でルールを捏造してはいけません。

## 入力（未指定なら既定値を使う）

- 対象範囲: ワークスペース全体（除外: 生成コード、vendor/、node_modules/、dist/、build/、バイナリ、ロックファイル）
- 出力先: `docs/code-catalog.md`（新規作成。既存があれば上書きせず差分案を提示）
- 深さ: 標準（主要モジュールは全数、その他は代表サンプル）

## 絶対ルール

1. **読み取り専用**。調査対象のソースコードは一切変更しない。変更するのは出力先ファイルだけ。
2. **全項目に証拠**。各パターンには必ず「該当数 / 母数」と代表例の `ファイルパス:行番号` を2件以上付ける。数えられない主張は書かない。
3. **採用率で格付けする**。
   - 80%以上: 「確立した作法」
   - 60〜79%: 「傾向あり（例外も定着している）」
   - 60%未満、または流派が拮抗: カタログのルール欄には入れず「分裂項目」に回す
4. **意図的例外を犯罪扱いしない**。コメント・命名・設定で意図が読み取れる逸脱は「登録済み例外」候補として理由つきで記録する。
5. 分からないことは「不明」と書く。母数が3未満のパターンは格付けせず「サンプル不足」とする。

## 手順

### フェーズ0: 棚卸し
- 言語・フレームワーク・主要モジュールの構成を把握する
- 既存の明文ルールを先に収集する: README、CONTRIBUTING、AGENTS.md、copilot-instructions、
  linter / formatter / 型検査の設定、CI設定、CONVENTIONS 系ドキュメント
  → これらを「明文ルール」として分離記録する（暗黙パターンと混ぜない）

### フェーズ1: 処理ファミリーの発見
コードを「同種の処理の集まり（ファミリー）」に分ける。例（実在するものだけ採用し、名前は実コードに合わせる）:
外部API/HTTP呼び出し、ファイルIO、DB・永続化アクセス、例外処理、ログ出力、入力検証、
設定読み込み、並行・非同期処理、リトライ、リソース解放、テストの書き方、UI/画面部品、CLI引数処理

各ファミリーについて、所属する実装箇所の総数（母数）を数える。

### フェーズ2: チェック項目マトリクス
各ファミリーごとに「その処理なら当然やっているはずの項目」を、実コードから抽出して列にする。
例（HTTP呼び出しなら）: タイムアウト指定 / エラー処理 / リトライ有無 / ログ / 戻り値の検証 …
そして実装ごとに ○ / × / 該当なし を付けた表を作り、項目ごとの実施率を算出する。

### フェーズ3: 横断作法の抽出
ファミリーを跨ぐ作法を数える:
命名（関数・変数・ファイル）、モジュール分割と依存方向、import の方針、コメントの書き方と量、
テストの配置と粒度、エラーメッセージの書式、定数・設定値の置き場所

### フェーズ4: 逸脱の予備記録
カタログ化の過程で見つけた「多数派から外れた箇所」は、断定せず別節に候補として記録する。
各候補に「多数派との差分」と「意図的に見える根拠の有無」を添える（本格監査は別プロンプトで行う）。

## 出力フォーマット（docs/code-catalog.md）

```markdown
# コードカタログ: <プロジェクト名>
生成日: <日付> / 対象コミット: <可能なら> / 母数の取り方: <一言>

## 1. 明文ルール（既存ドキュメント・設定から）
| ルール | 出典 |

## 2. 処理ファミリー別カタログ
### <ファミリー名>（母数 N）
| チェック項目 | 実施率 | 格付け | 代表例（path:line） |
（格付け: 確立 / 傾向 / 分裂）
模範ファイル: このファミリーの作法を最もよく体現する1〜2ファイルと、その理由

## 3. 横断作法
（同形式の表）

## 4. 分裂項目（ルール化しない）
| 項目 | 流派A（n件・例） | 流派B（n件・例） |

## 5. 登録済み例外の候補
| 箇所 | 多数派との差分 | 意図的と読める根拠 |

## 6. 逸脱候補（予備）
| 箇所 | 差分 | 意図の根拠 | 危険度仮説（高/中/低＋理由） |

## 7. 不明・サンプル不足
```

## 完了報告
チャットには要約だけを返す: ファミリー数、確立した作法の件数、分裂項目の件数、
逸脱候補のうち危険度「高」の件数とその箇所。カタログ全文は貼らない。

## やらないこと
- 一般的なベストプラクティスの説教（このコードベースで実測できていないもの）
- スタイルの好みの断定（formatter が決める領域は「設定に委ねられている」と記録するだけ）
- 逸脱候補の自動修正
